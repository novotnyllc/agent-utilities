# Summary

The user's direction: **"USE FUSION TO DO THIS, don't reinvent stuff you don't need to"** — and none of it needs to run offline. That falsifies the premise under plans 005–009's architecture. Those plans built a host-side pure-Python planner with a dumb Fusion-side executor so that everything could be proven under `scripts/test.sh` with no Fusion running. The offline requirement was justified by a CI that does not exist; the real acceptance path has always been a live Fusion run. The constraint forced stdlib-only numerics, which forced hand-rolling symmetric eigen-decomposition, RANSAC, Potts-ICM segmentation, a spatial grid index, NURBS evaluation, covariance machinery and statistical tail functions — roughly 9,200 lines of numerics and transport, with `mesh_segmentation.py` alone at 3,087 lines. The tradeoff was paid for nothing.

The re-architecture: **the pipeline runs inside Fusion**, as a real Python package delivered through the existing module-bundle cache, using Fusion's geometry kernel and numpy for everything they already do, and keeping our code only for the judgement Fusion has no opinion about — whether a fit is *justified*, whether a relationship is *licensed*, whether a claimed edit *actually rebuilds*. That judgement layer — disproof gates, uncertainty propagation, the kinematic router's verdicts, relationship adoption, the closed-vocabulary program, the perturbation proof — is the product and survives intact. Everything else is measured against one question: *does Fusion (or numpy) already do this — reliably, in the regime real scans occupy?* Where the answer is yes (linear algebra, ray casting, spline evaluation, measurement, transport-by-not-transporting), ours is deleted outright — not wrapped, not kept as a fallback. Where Fusion computes but cannot be trusted at scale (Convert Mesh), ours stays as the workhorse and Fusion's output is a gated candidate.

The governing line, stated once and applied everywhere below: **prefer Fusion for computing geometry, never for judging it — and do not assume it computes well at scale.** Delete what numpy or a *reliable* Fusion API replaces; keep everything that judges whether a result is justified, and keep our own geometry path wherever Fusion's is unreliable in the regime that matters (Convert Mesh at scan-sized meshes being the proven case). The rung-1 implementation (green on `feat/mesh-irregular`, PR #44, 838 tests; unfinished planner preserved on `wip/mesh-irregular-u3-planner`) supplies the two clearest examples of the judgement category, validated live — the kinematic router and the fit-point/refusal budgets — and both are salvaged in the migration, minus their hand-rolled numerics.

A live probe run during this design settled the biggest open question: **`PrismaticMeshConvertMethodType` exists and `MeshConvertFeatures` is API-reachable** (V12). Fusion will convert a scanned mesh to a prismatic B-Rep natively, handing back faces whose `face.geometry` is a `Plane`/`Cylinder`/`Cone`/`Sphere`/`Torus`. And — per the user — **Fusion's converter doesn't always do a good job, especially with a lot of triangles**. That failure mode is correlated with mesh size, which is exactly the regime real scans live in (200k–2M triangles). So the design places convert precisely: it is **an accelerator, invoked per region on small coherent patches after our segmentation partitions the mesh, and an input to be verified — never an authority, and never fed a 2M-triangle body by reflex**. Every converted face passes the same disproof gates our own fits face; our detection engine (RANSAC + exact fitters, on numpy) is **the workhorse that scales**, not a fallback; where both sources fit the same region they are compared, with agreement recorded as corroboration and disagreement surfaced, never silently resolved. Per-region provenance (`fusion-convert` / `native-fit`, with triangle count as a first-class predictor) is recorded in the fit record, so the tool learns where convert's reliability boundary actually sits instead of rediscovering it per part.

Expected deletion, revised honestly downward from earlier drafts of this design: **~4,000–4,500 source lines** plus the tests bound to them. What goes without argument: the hand-rolled linear algebra, the inside/outside heuristics, the NURBS interpolant model, hand measurement/OBB code, the host↔Fusion transport, and the generated-executor/byte-pinning layer. What stays: segmentation (now load-bearing twice over — it partitions the mesh for per-region convert), the detection engine, the disproof gates, and every threshold and refusal in the judgement layer — the converter being unreliable at scale is precisely why.

Two constraints survive the pivot unchanged, because they are why this codebase is trustworthy:

1. **Probe-and-verify.** Every API claim below is either a fact verified live on 2026-08-19 against the user's Fusion (2.9.6, Python 3.14.0, `cp314`, `macosx-10.15-universal2`) or a labelled assumption with the probe that settles it. Probing is how we know `NurbsSurface.create`, `faceGroups`, and `calculateCollisionsWithRay` exist at all — and how we know `TemporaryBRepManager.createFromMesh` does *not*.
2. **Verification must not assert more than it verified.** This was never about test suites; it is about the reports the tool emits. Hash-bound evidence, append-after-success `checked` lists, declared thresholds with rationales, refusal over invention — all unchanged.

# Assumptions — each labelled, each with its probe

None of these blocks the architecture; each selects between two designed outcomes.

- **P2a — prismatic convert entitlement.** The enum and feature collection exist (V12); whether the operation *executes* without a Design Extension license on this account is not established. Probe: run one prismatic conversion on a small mesh. Refusal designed in advance: `convert-unavailable`, naming the method type and the entitlement. Because the native path is the workhorse, an entitlement refusal costs the accelerator, not the pipeline.
- **P2b — prismatic convert output shape, quality, and scale boundary.** Expected, not verified: the conversion produces **one `MeshConvertFeature` timeline item holding a B-Rep body** — not a parametric feature tree; its faces carry analytic `face.geometry` for regions Fusion could fit, and something else (many small faces, or failure) where it could not. Known from use (the user's report): quality degrades with triangle count — over-/under-segmentation, missed features, give-ups — which is why convert is invoked **per region** and gated, never trusted. Probe: convert a marketplace STL and a real scan at several sizes; inspect the timeline, walk `body.faces` recording `surfaceType` histograms, and measure per-face residuals against the source mesh. The record — keyed by triangle count — is the first data point of the reliability boundary the provenance field then keeps learning.
- **P1 — `faceGroups` semantics and quality (downgraded to candidate input).** The property exists (V3) but `MeshFaceGroup`/`MeshFaceGroups` members could not be inspected without a mesh body loaded — inconclusive. Segmentation stays ours regardless (it is load-bearing for per-region convert); if the probe shows `faceGroups` carries meaningful groups on imported meshes, they become a cheap *candidate partition* checked against our own — agreement statistic recorded, exactly the KTD4 discipline from 005. Probe (same session as P2b): group histogram on an imported STL, generate groups where absent, compare boundaries against measured dihedral creases.
- **P3 — `calculateCollisionsWithRay` semantics.** Existence verified (V4); unknown: return shape (hit points? count?), behaviour on grazing/coplanar hits and on open meshes. Probe: cast against a known closed mesh and a deliberately holed copy. Inside/outside by hit parity is only claimed when `isClosed` is true — an open mesh refuses the containment question, as today.
- **P4 — `measureManager` accepts transient geometry.** Distances/angles between fitted transient surfaces and curves, not just design entities. Probe: `measureMinimumDistance` between two transient cylinders. Fallback is trivial (the closed-form distance between fitted parameters — a few lines, not a module).
- **P5 — a route from `NurbsSurface` to a held body.** `BRepBodyDefinition` (or similar) accepting V1's surfaces to produce a body a base feature can hold. Probe: construct one patch, attempt the round trip. Only the optional "surfaced remainder" outcome depends on this.
- **P6 — loft/sweep recompute under parameter and section edits** (009's C5–C7, unchanged). First loft/sweep emission run settles them.
- **P7 — in-document trial geometry is cheap and cleanly deletable.** The in-Fusion fitting loop creates trial sketches/splines/features and deletes them; probe that `deleteMe` on a trial sketch leaves no timeline residue and that a scratch sketch in a scratch component does not pollute undo beyond one group. Fallback: trial curves via transient `NurbsCurve3D` evaluators (V2) where a real sketch is not needed.

**What stays ours — either because Fusion has no opinion about it, or because Fusion's version is unreliable where it matters:**

- **The disproof gates.** Support span, residual structure along the primitive's own parameterization, Moran's I on the mesh graph, spatially blocked held-out residual, parsimony/F-tests. Fusion will fit a cylinder to anything — via convert it *does* — and it will never tell you the fit is *unjustified*. The gates now judge two sources instead of one, which makes them more central, not less. Rewritten on numpy (smaller), semantics unchanged.
- **Segmentation and the detection engine.** Not judgement but geometry we must own anyway: convert degrades with triangle count (P2b), so the native RANSAC-plus-exact-fitters path is the workhorse for scan-sized meshes and segmentation is the partition that lets convert run per-region at all.
- **The kinematic router and the fit-point/refusal budgets** (rung 1, live-validated). The motion verdict — is this disclaimed wall an extrusion, a revolution, a helix, or nothing — and calls like "three corner-free arcs are a biarc approximation, not three radii" are decisions no Fusion API makes.
- **Noise gating before segmentation trust** (005 KTD5) and every caller-declared threshold with a rationale.
- **Relationship inference and licensing** — proposals with measured deviations, adopted only by recorded decision; `equal_radius`, `tangent`, coaxial/parallel/perpendicular/symmetric/nominal.
- **Datum-frame derivation with total, deterministic tie-breaks** and the `frame-ambiguous` refusal.
- **The reconstruction program** — versioned, hash-bound both directions, closed vocabulary, declarative, refusing anything unknown (`reconstruction_program.py`, essentially untouched).
- **The constraint ladder policy** (006 D3): snap-with-recorded-deviation, one at a time, displacement-checked, budgeted, rollback. Fusion's solver executes; the policy of what to ask it and what to do when it disagrees is ours.
- **The editability proof** (006 D7): declared observables, perturb–assert–restore–assert, `parameter-inert` as failure, `checked` built append-after-success. `designType` is never evidence.
- **The refusal vocabulary and the evidence chain** — closed, documented, fail-closed.

# Prismatic convert: accelerator, not authority

The design's position on `MeshConvertFeatures` (V12), stated precisely, because both extremes are wrong — ignoring it reinvents fitting Fusion often gets right; trusting it ships the silent degradation the gates exist to catch.

**What it gives us.** Segmentation and analytic fitting in one native operation, where it works: a B-Rep body whose faces expose `face.geometry` as the exact primitive types our vocabulary uses (V6), plus face adjacency for free. On small, clean, coherent patches that is a fast, high-quality candidate source.

**What it does not give us — each item is a reason this project still exists:**

- **Not a feature tree.** Expected (P2b, labelled): one `MeshConvertFeature` timeline item holding a body — no sketches, no dimensions, no parameters, nothing the perturbation proof could exercise. The emission stage remains the entire deliverable of issue #20; convert is a front end to it at best.
- **Not a verdict.** Convert hands over a `Cylinder` face; it does not say whether the triangles underneath support it, whether the residuals are structured, or whether a feature was quietly swallowed. Nobody gives you a verdict on geometry — that gap is the product.
- **Not reliable at scale.** Per the user, quality degrades with triangle count — the regime real scans occupy. A convert that "succeeds" on a 1M-triangle mesh with faces that fail the gates is the common failure, not the exotic one.

**The operating discipline:**

1. **Per-region invocation.** Our segmentation partitions first; convert sees a small coherent patch, never the whole scan. One region failing loses one region. *Decimate-before-convert is rejected*: it would produce fits against a mesh that is not the hash-bound one — an evidence-chain violation — and throws away the precision the fits need.
2. **Same gates, both sources.** Every converted face is audited against the anchor mesh exactly as a native fit would be. Failing faces are rejected with the same named reasons; the region falls through to the native path.
3. **Comparison where both fit.** Agreement within uncertainty is recorded corroboration; disagreement beyond it is `fit-source-conflict`, surfaced in the fit record, never resolved by silent preference.
4. **Provenance with a size predictor.** Every accepted fit records `fusion-convert` or `native-fit` plus the region's triangle count, so the reliability boundary is learned from evidence across runs rather than rediscovered per part.
5. **Fallible by default.** Named refusals: `convert-unavailable` (P2a entitlement), `convert-failed` (operation error or give-up), `convert-timeout` (declared wall-clock budget per region), `convert-rejected` (faces failed the gates — with the counts). None of these stops the pipeline; all route the region to the native path, recorded.

# The revised execution model

**Unit of work: a pipeline stage, invoked in Fusion, leaving a hash-chained record.** The pipeline is one Python package (`fusion_design.recon`) delivered by the existing module-bundle cache (`module_cache.py`, 416 lines — kept as-is; content-addressed, `O_NOFOLLOW`, verified imports; exactly the delivery mechanism this pivot needs). The MCP host sends a small, stable bootstrap through the discovered Python-execution capability; the bootstrap imports the cached package and calls `run_stage(stage_name, spec)`. The stages:

1. `probe` — the capability/tag/API probe, extended with P1–P7; read-only; record keyed by Fusion version.
2. `anchor` — canonicalize the bound mesh (vertices, triangles, group ids, units, transform) from `nodeCoordinatesAsDouble`, hash it, write the dump into the session evidence directory. The dump no longer transports anything; it is the **evidence anchor** the whole chain binds to.
3. `segment-fit` — noise gate, our segmentation (with `faceGroups` as a checked candidate partition, P1), then per region: prismatic convert where entitled and within budget (candidates with provenance `fusion-convert`), the native RANSAC/exact-fit path (provenance `native-fit`), the disproof gates over both, source comparison, router verdicts on disclaimed regions. Produces the fit record.
4. `frame-relate` — datum frame, relationship proposals. Produces frame + proposal records.
5. `plan` — archetype planning into the reconstruction program (unchanged artifact, unchanged validator).
6. **— review pause —** the program and records are on disk; the agent (and user) read them before anything mutates. This gap is deliberate and survives from the old architecture: fit and emit are separate invocations with a human-readable, hash-bound artifact between them.
7. `emit` — re-derive the anchor hash from the live mesh (refuse `dump-hash-mismatch`), then planes → parameters → sketches → constraints → dimensions → features in program order, with the D3/D8 ladder, rollback, and replan loop — now in-session: a loft deviation iteration is a function call, not a host round-trip, so 009's "minutes per iteration" loop becomes seconds.
8. `prove` — the perturbation proof, unchanged in substance.
9. `grade` — asymmetric deviation verdict via `compareWith` / ray casting against the immutable anchor.

**A boundary correction this model absorbs for free.** The rung-1 worker found that 009's section-constancy confirmation *cannot* live in `plan_archetypes`: the planner holds only the fit record and has no triangles. That was a symptom of a general distortion — several decisions were pushed host-side purely to be offline-testable, away from the geometry they judge. In this model the symptom dissolves: `plan` and `emit` both run where the anchor mesh, the converted bodies, and the evaluators are, so geometry-dependent confirmations (section constancy, spline deviation, loft deviation) sit in the stage that owns the geometry, and the fit record stops having to smuggle triangles forward.

**State between stages** is the document plus the session evidence directory (Fusion and the host share a filesystem): per-stage JSON records, each carrying the anchor hash, the manifest hash, the upstream record hashes, and a CLI-issued nonce. Reports still stream through the `FUSION_DESIGN_REPORT_BEGIN/END` stdout protocol for the MCP channel; bulk artifacts live in the evidence directory.

**How the binding discipline survives — item by item, because four audits were about it:**

- The anchor hash is computed from the live mesh in stage 2 and **re-derived from the live mesh before any mutation** in stage 7. A mesh edited between fit and emit still refuses. Running in-process changes where the hash is computed, not what it binds.
- The program stays a **data artifact with a closed vocabulary and a version**, validated by the same `_reject_unknown_fields` machinery, reviewed at the pause. In-Fusion execution does not merge fit and emit into one opaque act.
- `checked`/`created` lists are still built append-after-success by the code that ran the check.
- Reports still carry the nonce and full hash chain, and the **host-side report validator is kept** (it is small, it runs anywhere, and it is what stops an agent — or a bug — from presenting a report that asserts more than it ran).
- Refusals are still total: a failed emission rolls back and produces no geometry; `replan-without` / `replan-with-sections` remain explicit recorded commands.
- Every stage record cites the probe record for the Fusion version it ran under.

**Main-thread honesty and the scaling story:** everything here runs on Fusion's UI thread; `adsk.doEvents()` is pumped between stages as today. 007's pure-Python budget was 2–6 minutes at 200k vertices; numpy changes that in our favour, and the estimates below are stated so the first live benchmark can falsify them rather than a vague "fast" surviving unmeasured. Vectorized per-triangle stages (normals, adjacency, dihedrals, noise floor): **sub-second at 200k triangles, a few seconds at 2M**. RANSAC with vectorized inlier scoring plus the disproof gates: **seconds at 200k, tens of seconds at 500k, low minutes at 2M** — dominated by the superlinear pieces (fit-driven splitting, ICM sweeps), which is where the practical ceiling sits. **Expected ceiling: ~2M triangles** on the UI thread with event pumping; the **triangle budget stays** and refuses above the declared limit — its rationale is now three-fold: the superlinear tail, the noise-not-information argument (unchanged from 005 R2), and UI-thread occupancy. Per-region convert calls carry their own declared `convert-timeout` so one large region cannot stall the stage.

# Verification model

Per the user's direction, offline coverage is a non-requirement and does not shape this architecture. The verification path is:

- **Live acceptance is the gate.** The issue's acceptance case — marketplace STL through anchor → fit → program → emit → prove → grade, Fusion version recorded, coverage fraction and unreconstructed regions listed — plus stage-level self-checks that run in the same session (each stage validates its own inputs' hash chain and refuses on any mismatch).
- **The reports remain the contract.** Every honesty mechanism above (nonce, hash chain, append-after-success, closed labels, declared thresholds) is enforced in the running code and checked by the retained host-side report validator. "Verification must not assert more than it verified" was never a property of a test harness; it is a property of the artifacts, and the artifacts are unchanged.
- What survives of the old suite is incidental: pure-logic pieces (program validator, record schemas, datum tie-breaks) still import host-side and their tests are cheap to keep where they cost nothing. Tests bound to deleted code are deleted with it, and no doubles harness is built or maintained for the in-Fusion layer.

# numpy and dependencies

- **numpy is a hard requirement of the reconstruction feature.** Installed once via pip against **probed** tags (`--python-version/--implementation/--abi/--platform --target`, values from the probe record, never literals), from a pinned lock with `--require-hashes`, into the `ManuallyInstalled` directory already on Fusion's `sys.path`; resolved set and hashes recorded in the evidence chain against the Fusion version. A missing or tag-mismatched numpy is a refusal — `dependency-unavailable`, naming the package, the probed tags, and the exact pip command that fixes it — never a silent slow path. **All pure-Python fallback numerics are deleted**; a fallback for a dependency we control the installation of is code we do not need.
- **Fusion auto-updates its Python.** The probe record makes an interpreter bump *detectable*: the tag set changes, the import refuses, the refusal names the re-pin. That is the designed failure mode, and it is loud.
- **scipy is banned from the critical path** until a wheel exists for Fusion's interpreter (none for `cp314` today — V11). The ~60 lines of stats tails stay ours; sparse solves stay out of scope.
- Host-side Python needs numpy too (for whatever logic remains host-runnable, and the report validator does not need it). Version skew between host and Fusion numpy is recorded in the evidence, not assumed away.

# Freeform, reconsidered

V1/V2 falsify 009's API-side claim: Fusion **can hold** constructed NURBS curves and (pending P5's body route) NURBS surfaces. What V1 does **not** change is the distinction 009 got right, restated precisely because it must not blur:

- A surface Fusion can **hold** is geometry in the document: visible, exportable, usable by CAM, measurable. If it arrives through a base feature it recomputes without responding to any parameter — it is frozen the moment it is born.
- A feature the user can **edit with a dimension** is one whose driving values are user parameters or live sketch geometry, provable by the perturbation loop. No constructed NURBS patch is that, on any API path that exists: no dimension drives a control point, and `U5` has nothing to perturb.

What genuinely changes:

1. **The editable-freeform ladder (009 rungs 1–3) gets stronger, not different.** Fitted splines are now a measured quantity (V10: degree-5 rational, interpolating, movable fit points) driven live by the in-Fusion loop; loft/sweep/ruled are verified-present features (V5); the loft refinement loop is in-session and fast. "Editable" continues to mean exactly what 009's honesty table says per rung, and that table stands.
2. **A new, optional, clearly-labelled outcome: the surfaced remainder.** On P5 success, regions the ladder cannot claim may be fitted (numpy tensor-product least squares is now feasible for regions with a trivial parameterization — height-field or four-sided; arbitrary-region parameterization still needs sparse solvers we do not have) and delivered as smooth **reference surfaces** in a base feature, explicitly labelled non-parametric, counted in a separate `surfaced_nonparametric` bucket that is **never** added to `covered_area_fraction`. This is strictly better reference geometry than a faceted mesh for downstream manufacturing, and strictly not reconstruction. If P5 fails, the remainder stays reference mesh, as today.
3. **`ruledSurfaceFeatures` remains folded into loft** (009 rung 4's YAGNI holds — a ruled transition is a two-section loft).

The over-claim boundary in one sentence, for the doctrine: *we emit editable features where a dimension can drive them, we hold labelled reference surfaces where it cannot, and the report never lets one count as the other.*

# Report-back summary

- **Revised architecture:** the whole reconstruction pipeline runs inside Fusion as a cached, verified Python package invoked stage-by-stage through the existing MCP execute capability. The governing line: **prefer Fusion for computing geometry, never for judging it — and do not assume it computes well at scale.** Prismatic Convert Mesh (verified API-reachable, V12) enters as a *per-region accelerator* whose fitted faces are candidates under the same disproof gates as our own fits, with provenance and source-comparison recorded; the native segmentation + RANSAC + exact-fitters path, rewritten on numpy, is the workhorse for scan-sized meshes because convert degrades with triangle count. The judgement layer — gates, uncertainty, router verdicts, relationship licensing, datum tie-breaks, the closed-vocabulary program, the constraint ladder, the perturbation proof — is the product and is untouched in semantics. The hash-bound anchor, the review pause at the program boundary, and the full refusal/evidence discipline survive intact.
- **Deletion, revised honestly:** **~4,000–4,500 source lines** plus their tests — hand linalg, per-triangle CPython loops, grid index, orientation winding, the NURBS interpolant model, host↔Fusion transport, and the generated-executor/byte-pinning layer. Detection, ICM, segmentation, and every gate stay: Fusion's converter being unreliable at scale is why.
- **Fusion genuinely replaces:** linear algebra and bulk numerics (numpy, in-Fusion, confirmed live), inside/outside (`calculateCollisionsWithRay`), NURBS evaluation (real fitted splines + `SurfaceEvaluator`; V10 gives the interpolant family), measurement/OBB (`measureManager`), loft/sweep/ruled as native features, and — per region, gated, provenance-tracked — segmentation-plus-fitting via prismatic convert where it holds up. **Only looked replaceable:** the detection engine (convert is size-fragile), the disproof gates, thresholds, the kinematic router, relationship licensing, datum determinism, program vocabulary, editability proof, mesh sectioning (no mesh-section API — settled, V13), and the stats tails (no scipy cp314 wheel).
- **Verification:** offline coverage is a non-requirement per the user; live acceptance plus self-checking hash-chained stages and the retained host-side report validator are the gate; every report-honesty mechanism survives unchanged.
- **Scaling, priced:** vectorized stages sub-second at 200k triangles and a few seconds at 2M; detection-plus-gates seconds at 200k, tens of seconds at 500k, low minutes at 2M; practical UI-thread ceiling ~2M with the triangle budget refusing above it; per-region convert calls under their own timeout. Estimates stated to be falsified by the first live benchmark.
- **Migration:** M0 probes including a real multi-size prismatic conversion trial (P2a/P2b settle first, they shape M2) → M1 runtime beachhead → M2 native segment/fit with per-region convert and rung-1 router/budgets salvaged → M3 native frame/plan + transport deletion → M4 native emit/prove + generation-layer deletion → M5 grade + doctrine + acceptance → M6 optional freeform. The old path keeps working until each native stage runs live; no step leaves the tree broken.
- **Honest unknowns, each with its probe:** prismatic convert entitlement (P2a), its output shape and its quality-vs-size boundary (P2b), `faceGroups` provenance on imported meshes (P1, downgraded to candidate input), the NurbsSurface→body route (P5). All outcomes are designed; only the accelerator's share of the work moves.
